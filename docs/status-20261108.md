# A1222 SPE and Polaris status — 8 November 2026

Canonical development remains in this repository, on `development`. The public forge consumes pinned exports and contributor-facing validation summaries.

## Verified progress

- GCC14 candidate patch17 corrects SPE subreg reload conversion. The original nine-check SPE C ABI probe passed on the physical A1222 using an explicitly selected fresh GCC14-built glibc 2.41 loader/libc/libm in a private temporary directory. The running system libraries were not replaced. QEMU user-mode still fails the rounding test with the same candidate: emulator and hardware results are distinct. Broader SDK regression, package and image acceptance remain open.
- Linux 6.12.113-tabor-modular boots on the A1222 with network/SSH. The protected Polaris trial qualified its module against the running kernel, retained logs off-board and verified read-only USB root before binding. GFX/KIQ/compute/SDMA scratch tests passed, but these do not prove full GPU execution or scanout.
- The next measured failure occurs after `PPSMC_MSG_DPM_Enable` (0x14e), with PCIe error reporting about 45 ms later. Later SMU failures are cascading evidence. This is not a working graphical console; the bind timed out and SSH became unavailable.

## Source findings and limits

The display-clock voltage dependency fix is already in the pinned driver. Experiment0018 makes mandatory DPM initialization failures propagate instead of continuing; native extracted-function tests pass, but it has not been kernel-built or physically tested and does not repair the bus fault by itself.

The fresh audit establishes an endian defect in optional AVFS calibration: pre-swapped native constants copied as bytes differ between x86 and BE PPC. Frequency 30000 becomes a different device value on BE. The byte uploader preserves its input correctly. Whether this board took the calibration path remains unproven: an efuse bit, feature mask and cold firmware-start gate control it. No root-cause or display-recovery claim follows yet.

Historical Tabor did reach a desktop, with older Radeon configurations. Its vendor kernel enabled radeon and disabled amdgpu; that is useful context, not proof of RX560 support. Derfsss U-Boot/QEMU/MCP references are pinned and reviewed. The QEMU fork's AmigaOne/G5 work is a separate OS4 test route, not an A1222/SPE hardware model or physical Radeon validation.
