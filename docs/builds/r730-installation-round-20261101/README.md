## Debian installation gate: FAIL

The two private bundle packages are installed and dpkg audit is clean, but
individual Debian dbus/openssh-server/enlightenment/terminology/Xorg/xinit
packages are absent from the database. A bundle install is not equivalent to
running their actual maintainer scripts, triggers and dependency setup.
The new read-only audit rejects this root. Configured versus half-configured
fixture checks pass on the R730 native dpkg-query; this laptop lacks that tool.
The required-name list is a minimum state gate, not complete dependency proof.

The existing E screenshot's module dialog is independently explained by its
profile requesting lokker, mixer, music-control and polkit while the build
explicitly disables them. Do not suppress the dialog to claim success, or
attribute black client rendering to D-Bus without further evidence.

Next implementation: generate proper target-ABI Debian binary packages from
pinned source packaging, including dependency metadata, conffiles and generated
maintainer scripts. Bootstrap their dependencies and configure them inside the
SPE guest. Preserve the resulting whole installed root and /var/lib/dpkg,
including info/updates/triggers, accounts, alternatives and generated config.
Do not copy raw upstream debian/*.postinst scripts into our bundles: debhelper
substitutions and dependencies must be generated by the package build first.
Keep source compatibility patches separate from machine configuration. Support
only QEMU and A1222. Retest E and services after package configuration.
